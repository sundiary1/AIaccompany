# Mind Island V0.7.1：真实 AI 长期记忆专项验收

2026-10-25。专项验收完成；保留 V0.7 成果，未开发 V0.8。

## 结论

使用现有 **api.deepseek.com / deepseek-flash** 配置，真实验证了聊天完成、后台提取、SQLite 入库、新会话请求实际注入及明确偏好更新。发现并修复了句式预筛漏存、供应商分类差异、相关检索漏召回及跨主题明确更正处理问题；敏感/凭证/心理推断规则没有放宽。

真实供应商 HTTP 请求严格限制为 **8 次：4 次聊天、4 次提取**，没有超限或自动重试。后续全部为 Mock。最终测试库保存 3 条有效自动记忆，雨天偏好已更新为晴天，旧内容仅留在版本记录。正式用户数据库未被写入测试记忆。

## 1. 检查与真实触发机制

已阅读 `docs/history/MEMORY_DEMO_V05.md`、`docs/SANDPLAY_DEMO_V07.md`，以及当前 `memory_worker.py`、`memory_rules.py`、`memory_models.py`、`memory_schema.py`、`repositories/memory_repository.py`、`repositories/conversation_repository.py`、`provider.py`、`chat_routes.py`、`database.py`、`main.py`；检查了前端信箱、授权、状态轮询、聊天请求和 SSE 处理。

实际链路：

1. 普通聊天收到消息时取得当前授权 epoch，并从 SQLite 检索可用记忆；前端不能指定系统提示词或可信记忆。
2. AI 回复完整生成并成功保存为 completed 后，`ConversationRepository.finish()` 在同一事务的 SAVEPOINT 中插入唯一 `memory_jobs` 任务；来源消息与授权时间/epoch 必须有效。
3. 应用 lifespan 启动独立单 worker：空队列约 1 秒轮询，有任务后约 .15 秒继续处理。流式回复不等待提取完成。
4. worker 原子领取 pending → running；先筛查整条用户消息的敏感内容、凭证、推断/假设和支持的稳定表达。符合条件才调用真实提取器。不符合时 completed + 0 新增，不代表调用过模型。
5. LLM 只收到真实用户消息及有限已有记忆参考，不收到 AI 回复作为用户事实依据。
6. 输出通过 JSON/Pydantic、来源 UUID、逐字完整分句、类别与内容规则校验，再在事务内去重、更新或标记待核对。提交前再次核对授权 epoch、消息存在及回复完成状态。
7. completed 表示处理结束；必须结合 provider_calls、added_count / updated_count / review_count / skipped_count 和实际 memories/source/version 行判断是否保存成功。

失败、取消、超时、安全响应、已完成请求重放及临时聊天不触发新的有效提取。启动恢复 pending；未知结果的 running 转 failed/interrupted，不自动重复收费。每条来源用户消息仅有一个任务；人工重试有次数上限。

测试库最终 **6 项任务全部 completed，pending/running/failed 均为 0**。没有发现 worker 未启动或队列积压；初始漏存的原因是规则提前跳过，而非 DeepSeek 未连接。

## 2. 默认开关、授权与 UI 使用

新数据库中 `auto_extract=0`、`use_memories=0`，真实基线测试在授权前确认了这两个默认值。本轮未修改正式库授权，正式库两开关仍为 **0 / 0**。

用户操作：打开 `/island-preview` → 点击小屿或“与小屿聊聊” → **记忆信箱** → 开启“自动记忆”，首次阅读说明并勾选授权。“自动记忆”首次授权会同时开启提取与使用；两项之后可以分别调整。

- **自动记忆**控制今后普通聊天完成后的任务排队和自动保存，不回扫旧对话。
- **使用已有记忆**控制正常聊天的记忆注入；也控制提取器能否获得已有记忆参考，不等于自动提取授权。
- 任一开关变化使旧 epoch 的未完成任务失效。临时聊天完全绕过记忆读取和任务创建。
- 信箱中可查看条目、分类、来源、更新时间及待核对状态，也可编辑、停用、删除。
- 过往 completed 但 0 新增的任务不会因本轮修复而自动重放。若要记住旧信息，应由用户今后重新表达或主动手动新增。

## 4. DeepSeek 请求、模型、提示词与成本

实际聊天模型与提取模型均为 **deepseek-flash**。提取模型取 `MEMORY_MODEL`，留空复用 `AI_MODEL`；地址和密钥只从服务端配置读取。未输出密钥，未修改供应商配置。

独立提取提示词：`backend/demo_ai/prompts/memory_extraction.txt`，与 `prompts/xiaoyu.txt` 陪伴人设分离。官方 DeepSeek 请求使用非流式输出、`response_format=json_object`、关闭 thinking；输出上限 768 tokens，提取超时 20 秒；聊天保持 SSE，输出上限 512 tokens。

一套传输层账本在每次真实网络发送前持久计数，包含聊天、提取和可能的回退请求；到第 8 次后拒绝继续发送。HTTP transport retries=0，没有隐式自动重试。重复排查使用 Mock 聊天回放，仅对提取器发必要的真实请求。

## 5. 自动提取与 SQLite 证据

原句：

> 我很喜欢下雨天，平时也喜欢去公园散步。我希望聊天的时候不要连续问我很多问题。

修复前，现有 derive 不支持“很喜欢”、逗号后的省略主语及“我希望聊天的时候…”；故任务 completed 但 provider_calls=0、memories=0。不能根据聊天回复中的“记住”或完成状态判断已入库。

修复后真实 DeepSeek 返回有效 JSON；来源 UUID、字面分句和服务端内容校验均通过。最终实际保存如下（全部为虚构测试数据）：

| 记忆 ID | 最终正文 | 类别 | 状态 |
| --- | --- | --- | --- |
| `ddef7c56-ce51-4030-96cc-b92963c5d217` | 用户喜欢晴天 | preference | enabled / approved，原雨天条目更新，revision=2 |
| `4d8573cd-e565-4944-ae3d-dbd225c77759` | 用户喜欢去公园散步 | preference | enabled / approved |
| `23556a01-7e0c-47bf-be4e-3d6e371ea54a` | 用户希望不要连续问我很多问题 | communication | enabled / approved |

全部 source_type=auto。来源表保留真实测试 user_message_id 及原文 evidence；正文由服务端从证据生成，不直接照存模型措辞。散步候选中模型曾返回 habit，服务端仅对已验证的“平时/平常也喜欢…”字面句式规范化为 preference，其他分类错误仍拒绝。

没有为了提取率放宽 SENSITIVE、SECRET、INSTRUCTION、UNCERTAIN 或 TRANSIENT 规则。没有保存模型自行推断的心理特征。

## 6. 跨会话实际注入

新建了与提取来源不同 UUID 的普通会话，发送：

> 周末我想出去走走，你有什么建议？

在实际发给 DeepSeek 的 HTTP 请求中检查到独立 `<memory_reference>` JSON，其中包含公园散步、交流节奏和雨天三条记忆。系统仍明确这些是不可信参考，不是指令，当前表达优先。读取数量最多 5 条、1000 字。

真实回复建议去公园，并自然提到用户喜欢散步和下雨天。该结论由出站请求与 SQLite 共同核验，不仅依赖生成文字。当前修复采用有限活动词关联补足词面匹配，不是通用语义或向量检索。

偏好更新后，又用真实验收库的独立副本及 Mock Provider 创建新会话，确认出站上下文包含晴天和公园，**不再包含旧雨天事实**，无额外真实调用。

## 7. 更新、冲突和用户编辑保护

真实发送：

> 我现在更喜欢晴天了，之前喜欢下雨天，但最近改变了想法。

真实结构化结果使用 `action=update`，target_id 指向原雨天记忆。服务端验证了完整明确更正句式、旧事实字面值、真实来源、条目来源和 snapshot revision，才在事务中更新同一 ID 的正文、标准化值、topic_key、来源和时间。

实际 job：updated_count=1，added_count=0，skipped_count=0。`memory_versions` 保留“用户喜欢下雨天”，有效记忆列表只有“用户喜欢晴天”，没有两条矛盾的有效天气偏好。

Mock 验证：不确定的相反事实进入 pending 并阻止关联旧事实注入；用户手动编辑过的旧偏好不会自动覆盖，跨主题更正也转为待核对；模型任意指定不相关 target_id 会被拒绝。当前规则只能可靠处理有限、明确的更正句式，其他复杂更正仍需用户在信箱编辑/核对。

## 已知限制与停止点

本轮证明了指定真实场景可运行，不代表所有自然语言都能自动提取或检索。规则有意保守；复杂表达、跨多轮隐含更正、超出活动词表的关联仍可能漏掉。用户可以手动编辑/新增，不能因此放宽敏感内容自动保存。

首 2 次聊天 usage 无法恢复，未宣称已核验完整费用。没有额外收费平台、数据库迁移、心理分析、长期记忆重写或新岛屿。SQLite/备份未加密；删除本机数据无法撤回已发送给供应商的请求。

默认代理已载入修复，正式授权开关保持原值，不自动扫描或补提取旧记录。真实 API 验收任务已结束；本轮到此停止。

## 后续姓名漏存修复（同日）
